# STAY ADD. 명세 실현 실행 계획

작성 기준: 2026-10-31 · 상태: 제안 실행안 · 범위: 기존 브랜드·제품·기술 명세 v1.0의 실현 경로.

이 문서는 개발을 모두 완료했다는 보고가 아니다. 현재 공개 프로토타입을 출발점으로, 검토된 학습 제품을 단계적으로 만드는 계획이다. 단계의 통과는 파일·검사 결과·검토 기록으로 입증한다. 날짜가 지났거나 화면이 완성됐다는 이유로 통과 처리하지 않는다.

## 1. 현재 상태와 목표의 차이

현재 공개 사이트는 정적 HTML/CSS/ES modules 기반이며, GitHub Pages에 자동 배포된다. 대형 타이포그래피·생성형 Hero·네 과목 진입부·개념 미리보기 4개·설명용 Lab 1개·Connect 주제 3개·검색·독자 문항 1개가 작동한다. Connect는 주제별 네 관점, 총 12개 설명을 가진다. 이것들은 제품 구조를 시험하는 초안이며, 검토된 정식 Lesson 4개나 완성된 교육과정으로 계산하지 않는다.

아직 없는 것은 확정된 시험 기준, 교육과정 전체 대응표, 정식 과목/주제/레슨 주소, 검토된 콘텐츠 생산 체계, 일반화된 평가 엔진, 여러 실험의 검증 체계, 개인 학습 기록이다. 현재 정적 형식은 초기 실험에 적합하며, 본격 콘텐츠가 생기는 단계에 맞춰 확장한다.

이번 모바일 개선은 장식용 방향·실행 기호를 Unicode 문자에서 SVG 도형으로 바꾸는 범위다. 본문의 반응식과 수학적 관계를 나타내는 기호는 학습 내용으로 유지한다. 문자 표시에 따른 차이가 존재하므로 UI 도형을 시스템 글꼴에 맡기지 않는다. [Unicode 표현 시퀀스](https://www.unicode.org/emoji/charts/emoji-variants.html)

목표는 세 번의 서로 다른 출시다.

1. **학습 흐름 검증판:** 한 개념의 질문→설명→실험→문제→연결이 끝까지 성립한다.
2. **네 과목 제한 베타:** 아래에서 정한 작은 범위를 검토하고 공개한다. 전체 시험 범위를 제공한다고 표현하지 않는다.
3. **정식 범위 출시:** 확정된 시험위원회·연도·응시 경로의 필수 학습 목표를 누락 없이 대응하고 검토한다. 개인화와 대규모 그래프는 별도 확장이다.

## 2. 먼저 고정할 결정과 책임

### 결정 기록

- **D-01 / 시험 기준:** 시험위원회, 과목별 syllabus 코드, 실제 시험 연도, 응시 경로/등급 체계를 제품 책임자가 결정한다. Cambridge는 후보이며 자동 확정하지 않는다. 후보 코드는 Chemistry 0620, Biology 0610, Physics 0625, Additional Mathematics 0606이다.
- **D-02 / 범위와 언어:** 첫 사용자의 수준, 설명 언어, 우선 과목/주제, 제한 베타의 포함·제외 항목을 결정한다. 현재 영문 브랜드 화면을 근거 없이 한영 전체 과정으로 확장하지 않는다.
- **D-03 / 검토 책임:** 과목별 검토자, 수학·모델 검토자, 출처와 권리 확인 책임자를 지정한다. 작성자 본인의 확인만으로 독립 검토 완료를 표시하지 않는다. 검토자를 확보하지 못한 콘텐츠는 초안/미검토 상태를 유지한다.
- **D-04 / 구조:** GitHub Pages 정적 배포는 유지한다. P1에서 Astro+TypeScript를 우선 후보로 검증하되, 콘텐츠 스키마·라우팅·JS 예산·기존 디자인 회귀를 통과한 경우 채택한다. 프레임워크를 바꾸는 것 자체는 완료 성과가 아니다.
- **D-05 / 공개 정책:** 콘텐츠의 검토 상태, 커버리지, 출처, 수정 기록을 어떤 문구와 페이지에서 보여줄지 결정한다. 공식 시험기관의 승인이나 공식 점수 예측을 암시하지 않는다.

시험 연도는 학습을 시작한 연도와 혼동하지 않는다. Cambridge의 syllabus 연도는 실제 시험을 치르는 연도에 해당한다. 과목 간 유효 기간도 다를 수 있다. 예를 들어 공식 페이지는 Chemistry의 2026–2028 자료와 Additional Mathematics의 2025–2027 및 2028–2030 자료를 구분한다. 따라서 네 과목에 하나의 기간을 일괄 적용하지 않는다. [Cambridge Chemistry](https://www.cambridgeinternational.org/programmes-and-qualifications/cambridge-igcse-chemistry-0620/), [Cambridge Additional Mathematics](https://www.cambridgeinternational.org/programmes-and-qualifications/cambridge-igcse-mathematics-additional-0606/)

특히 **제품의 학습 깊이 CORE/DEEP/BEYOND와 시험기관의 Core/Supplement/Extended 분류를 별도 필드로 둔다.** 제품의 CORE라는 이름만으로 시험 범위나 응시 경로를 판정해서는 안 된다.

### 책임의 구분

제품 책임자는 범위·언어·출시 여부를 결정한다. 개발 책임자는 구조·테스트·배포·복구를 담당한다. 과목 검토자는 과학·교육과정·설명 정확성을, 모델 검토자는 식·가정·단위·경계값을 검토한다. 학습자 검증 참여자는 사용성 관찰을 제공한다. 역할은 겸할 수 있지만 독립 검토가 필요한 증거를 자기 검토로 대체하지 않는다. 현재 이름이 지정되지 않은 역할은 미지정 상태로 기록한다.

## 3. 단계별 실행 순서

의존 경로는 **P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7**이다. P8은 필요성이 확인됐을 때 선택한다. 접근성·성능·교육 검토는 각 단계에서 수행하며, P7까지 미루지 않는다. P5의 제한 베타에도 해당 출시 품질 기준을 적용한다.

### P0. 기준선과 결정 확정

**선행 조건:** 현재 코드·브랜드 명세·공식 자료에 접근할 수 있어야 한다.

**작업:** D-01~D-05를 결정 기록으로 남긴다. 현재 각 기능을 ‘작동하는 초안 / 검토 완료 / 미구현’으로 구분한다. 원본 디자인, 배포 커밋, 스크린샷, 동작 검사를 기준선으로 보존한다. 모바일 SVG 아이콘 수정과 회귀 검사를 반영한다.

**산출물:** 결정 기록, 기능 현황 목록, 시험 기준 등록부, 검토 역할표, 초기 위험 목록.

**통과 기준 G0:** 시험 기준·언어·제한 베타 범위가 명시되고, 각 콘텐츠를 공개 검토할 책임자가 지정된다. 미확정 항목이 필요한 후속 작업은 진행하지 않는다. 아이콘 같은 독립적인 개선은 진행할 수 있다.

### P1. 재사용할 디자인과 정적 제품 구조

**선행 조건:** G0. 기준과 무관한 구조 실험은 격리된 브랜치에서 먼저 할 수 있다.

**작업:** 디자인 토큰, 타이포그래피, SVG 아이콘, 탐색, 표준 버튼·폼·상태·모달을 정리한다. `/explore`, `/subjects/:subject`, `/subjects/:subject/:lesson`, `/labs/:lab`, `/practice/:subject/:topic`, `/connect/:connection`, `/index`를 정적 출력 주소로 설계한다. 홈의 기존 hash 탐색은 작동하게 유지한다. 레슨 본문과 선택적 시뮬레이션을 분리한다. 수식 조판 방식을 보조 기술·폰트·번들 크기로 비교한다.

**산출물:** 구조 결정 기록, 표준 컴포넌트 묶음, 대표 페이지 1개씩의 실행 가능한 틀, 배포·되돌리기 절차.

**통과 기준 G1:** 320/375/768/1024/1440px에서 가로 넘침이 없고, URL 직접 접속·새로고침·뒤로 가기가 성립한다. GitHub 프로젝트 하위 경로에서도 자원과 링크가 맞는다. 핵심 본문은 JS 없이 읽을 수 있고, 계산 실험만 선택적으로 로드한다. 키보드 포커스와 상태 레이블을 확인한다. 기존 Hero와 브랜드 색상 회귀가 없다.

### P2. 콘텐츠 스키마와 교육과정 대응표

**선행 조건:** G0의 시험 기준, G1의 경로 구조.

**작업:** Subject, Topic, Lesson, Concept, Simulation, Question, Connection, SyllabusMapping, Reference를 명시적으로 정의한다. 과목별 공식 학습 목표를 식별 가능한 단위로 등록하고, 해당 문서 판본·항목·페이지·확인일과 연결한다. 선수 관계와 학제 간 연결을 서로 다른 관계 유형으로 저장한다. 필수 선수 관계만 비순환 검사한다.

**필수 필드:** 고유 ID, 제목, 과목, 학습 목표 ID, 깊이, 응시 경로 분류, 시험위원회·코드·연도, 선수 ID, 검토 상태, 작성/검토/수정 이력, 출처와 사용 권리, 관련 레슨/실험/문항 ID. 실험에는 변수·단위·범위·식·가정·난수 특성·검증 방식·한계를 추가한다. 문항에는 정답 규칙·단위·허용 오차·유효숫자 정책·힌트·해설·배점 근거를 추가한다.

**산출물:** 스키마, 공식 목표 등록부, 과목별 대응표, 빌드 검증기, 초안/검토/출시 상태 전이 규칙.

**통과 기준 G2:** 중복 ID, 깨진 참조, 선수 순환, 필수 메타데이터 누락, 시험 연도 불일치, 근거 없는 검토 완료 표시가 빌드를 실패시킨다. 해당 오류를 넣은 검사 fixture도 실패함을 확인한다. 커버리지의 분모는 확정된 공식 목표 집합으로 고정한다. 설명 문단 수나 링크 수를 커버리지로 쓰지 않는다.

### P3. Chemistry 한 주제의 전체 학습 흐름 검증

**선행 조건:** G2. 선택한 반응 속도 주제가 공식 기준과 매핑돼 있어야 한다.

**작업:** ‘왜 조건에 따라 반응 속도가 달라지는가?’라는 주제로 표준 Lesson의 여덟 요소를 구현한다: Question, Intuition, Principle, Interaction, Explanation, Application, Connection, Takeaway. 현재 개념 미리보기와 장난감 모델을 그대로 정식 자료로 승격하지 않는다. 충돌 이론의 정성적 설명과 Arrhenius 정량 모델의 범위를 구분한다. Arrhenius 식의 깊이 표시는 채택한 syllabus를 확인한 뒤 정한다.

**Lab 작업:** 목표·예측 질문·변수·시각화·수치·설명·비교·초기화·한계·출처를 완성한다. 계산 모델과 입자 표현을 분리한다. 수학적 일관성 검증과 실제 반응에 대한 실험적 검증을 별도 상태로 기록한다. 경험적 검증이 없으면 설명용 모델이라고 계속 표시한다. 조건·모델 버전·단위를 포함한 CSV를 재현 가능하게 만든다.

**문항 작업:** 독자 문항 6개를 시범 제작한다: 객관식 2, 수치 계산 2, 그래프 해석 1, 구조화 답변 1. 실제 시험 형식과 맞지 않으면 G0 기준에 따라 조정하고 이유를 기록한다. 서술형은 검증된 자동 채점 없이 모범 답안과 자기 점검으로 제공한다.

**산출물:** 정식 구조의 Lesson 1개, Lab 1개, 원문 문항 6개, Connect 1개 연결, 독립 검토 기록, 학습자 관찰 기록.

**통과 기준 G3:** 식·단위·질량 보존·극한·대표값·경계값을 독립 계산과 대조한다. 화면·그래프·CSV가 같은 모델 출력을 나타낸다. 한 학습 흐름을 키보드와 모바일에서 끝까지 완료한다. 학습자 5명 규모의 첫 관찰을 계획하되 이것을 학습 효과의 통계적 증거로 해석하지 않는다. 반복되는 막힘과 핵심 오개념이 남으면 수정 후 다시 확인한다.

### P4. Practice·Connect·Index의 공통 엔진

**선행 조건:** G3. 실제 한 주제로 입증된 데이터·컴포넌트만 일반화한다.

**작업:** 객관식, 단답, 수치/단위 입력, 그래프 해석, 구조화 자기 점검을 분리한다. 수치 답안은 허용 오차와 단위를 기준으로 판정하며 표현식 입력에 임의 코드 실행을 사용하지 않는다. Hint 1 방향 → Hint 2 방법 → Hint 3 중간 과정 → 전체 해설을 제공한다. 오답별 피드백은 문항 목표와 연결한다.

Connect는 conceptual / mathematical / systems 관계와 각 분야의 정의·단위·가정을 기록한다. 기존 변화율·에너지·피드백의 12개 관점을 다시 검토한다. 복잡한 대형 그래프 대신 검토된 소규모 연결 페이지를 우선한다. Index는 개념·기호·공식, 과목·깊이·시험 기준 필터, 일관된 결과 주소를 제공한다.

**산출물:** 문제 엔진, 힌트와 해설 구성, 검색 색인, 관계 스키마와 Connect 화면.

**통과 기준 G4:** 정답·오답·미입력·오차 경계·잘못된 단위·반올림·음수·0·과대 입력의 예상 결과를 문항별로 검사한다. 검색 결과는 실제 공개 가능한 주소만 가리킨다. 상태 변경과 오류가 보조 기술에 전달된다. 시험기관의 실제 점수와 같다는 표현을 쓰지 않는다.

### P5. 네 과목 제한 베타

**선행 조건:** G4와 과목별 검토 가능 인력. 콘텐츠 생산은 공통 스키마로 진행한다.

**출시 상한을 먼저 제한한다:** 각 과목 Lesson 3개·Lab 1개·독자 문항 8개, 총 Lesson 12개·Lab 4개·문항 32개. P3의 산출물은 이 총량에 포함하며 중복 합산하지 않는다. Connect는 기존 세 주제와 네 관점의 12개 설명을 검토해서 제공한다. 이는 제안된 베타 범위이며 전체 교육과정의 크기가 아니다.

**주제 후보:** Chemistry 반응 속도, Biology 확산/삼투, Physics 운동과 그래프, Additional Mathematics 함수 변화 또는 미분 시각화. 실제 포함 범위는 G0 시험 기준으로 확정한다. 각 Lab에는 최소 하나의 명시적 학습 목표가 있어야 한다.

**산출물:** 범위가 명시된 네 과목 베타, 과목별 탐색, 선수·후속 연결, 사용자 검증 기록, 해당 범위의 검토·출처 목록.

**통과 기준 G5:** 약속한 12/4/32 단위가 모두 완성되고, 출시 대상 전부가 독립 검토를 통과한다. Draft는 검토 완료 수에 포함하지 않는다. 본문·수식·단위·문항 해설·입력 오류·리셋·키보드·모바일·저속 환경을 검증한다. 핵심 학습을 막는 결함과 중대한 학술 오류는 0건이어야 한다. 공개 화면에는 베타가 다루는 공식 목표와 다루지 않는 범위를 보여준다.

### P6. 공식 교육과정의 검토된 범위 확대

**선행 조건:** G5. 수량을 늘리기 전에 제작·검토의 처리 시간을 측정한다.

**작업:** 선수 개념 순서에 따라 작은 단원 묶음으로 확장한다. 각 묶음은 목표 대응 → 설명 → 필요 시 실험 → 독자 문항 → 검토 → 배포를 거친다. 모든 목표에 억지로 시뮬레이션을 붙이지 않는다. 실제로 확인해야 할 실험 기술과 평가 목표도 대응표에서 추적하며 화면 설명만으로 실제 실험 수행 능력을 증명했다고 표현하지 않는다.

**지표:** 목표 대응률 = 필요한 레슨·평가 요소와 검토 증거를 가진 목표 수 / 확정된 전체 필수 목표 수. 검토율 = 독립 검토를 통과한 출시 단위 수 / 출시 예정 단위 수. 단원별 오류와 미검토 항목을 별도로 공개한다. 두 지표를 학생의 숙달도나 성적 예측으로 사용하지 않는다.

**통과 기준 G6:** 선택한 과목·연도·응시 경로에 대해 목표 대응률 100%, 출시 단위 검토율 100%, 잘못된 매핑·미해결 중대 오류 0건. 새 syllabus로 바뀌면 기존 판본을 조용히 덮지 않고 새 대응표와 변경 기록을 만든다. 하나의 과목/연도가 먼저 충족되면 그 범위를 명시해 먼저 출시할 수 있다.

### P7. 정식 공개를 위한 품질·운영 검증

**선행 조건:** G6의 선언할 범위. 아래 검사는 P1 이후 모든 배포에도 범위에 맞게 반복한다.

**접근성:** WCAG 2.2 AA를 목표로 자동 검사와 수동 검사를 함께 한다. 자동 위반 0건 외에도 incomplete 항목 검토, VoiceOver/NVDA 핵심 흐름, 키보드·스크린리더·터치, 200% 텍스트 확대·400% 재배치, 색상만으로 의미를 구분하지 않는지, 모션 감소, 드래그의 키보드/수치 대체 조작을 확인한다. 터치 대상은 제품 목표 44×44 CSS px로 설계한다. WCAG 2.5.8의 최소 24×24 CSS px 및 간격 예외와 이 제품 목표를 혼동하지 않는다. [W3C 대상 크기 설명](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

**모바일/브라우저:** 실제 iPhone Safari와 Android Chrome을 포함하고, 데스크톱 Chrome/Safari/Firefox/Edge의 지원 버전을 출시 시 기록한다. 320px 최소 폭, 세로/가로 전환, 소프트 키보드, 폼 확대, 긴 수식, 모달 스크롤, 포커스 복귀, SVG 표시를 확인한다. 데스크톱에서 폭만 줄인 검사를 실기기 검사로 기록하지 않는다.

**성능:** 초기 비실험 페이지 JS는 gzip 100 KB 이하, 폰트는 합계 80 KB 이하를 초안 예산으로 둔다. 시뮬레이션 코드는 필요할 때 읽고, 보이지 않는 Canvas와 숨긴 탭의 작업을 정지한다. 시뮬레이션은 저사양 장치에서 제어 응답과 렌더링 비용을 측정한다. 수치 갱신은 실제 표시 변화만 반영하고 스크린리더가 매 프레임 읽지 않게 한다.

실사용 목표는 LCP ≤2.5초, INP ≤200ms, CLS ≤0.1이며 모바일·데스크톱 각각 방문의 75번째 백분위수로 판단한다. 충분한 실제 데이터가 없으면 미측정으로 표시한다. Lighthouse나 로컬 측정 통과를 실사용 목표 달성으로 바꾸어 쓰지 않는다. 측정을 새로 도입하면 개인정보 처리와 데이터 최소화를 검토한다. [Web Vitals 기준](https://web.dev/articles/vitals)

**운영:** 공개 전 최종 출처·권리·보안·내부 링크 검토, CI 통과, 배포 커밋과 산출물 연결, 공개 URL smoke test, 직전 정상 버전 복구 연습을 수행한다. 잘못된 학술 내용은 해당 단원 노출을 제한하거나 Revision Required로 전환하고 수정 이력을 남긴다.

**통과 기준 G7:** 지원 기기 검사 기록, 접근성 미해결 사항의 판정, 성능 실험 결과와 미측정 항목, 최종 콘텐츠 검토, 되돌리기 검증이 모두 남는다. 중대한 결함은 해결 전 출시하지 않는다. 인증을 받지 않았다면 접근성 인증 완료라는 표현을 쓰지 않는다.

### P8. 선택적 확장: My Learning과 고급 Knowledge Graph

**선행 조건:** 핵심 학습 흐름의 실제 사용에서 필요가 확인돼야 한다. P7 정식 학습 범위의 필수 조건으로 계정 만들기를 요구하지 않는다.

**작업:** 먼저 기기 내 학습 기록의 의미·버전·내보내기/가져오기·초기화와 실패 복구를 설계한다. 여러 기기 동기화가 필요해질 때 별도 API·인증·사용자별 접근 제어·삭제/보존 정책을 설계한다. 정적 GitHub Pages에는 비밀 키나 서버 저장 기능을 넣지 않는다. 대규모 그래프는 검토된 관계가 충분할 때 관계 유형·필터·텍스트 대체·성능을 검증한다.

**통과 기준 G8:** 데이터 삭제·내보내기·동기화 실패·마이그레이션·권한 검사, 그래프의 키보드/스크린리더 대체 경로, 관계의 학술 근거가 입증된다. 계정 없이도 핵심 학습을 사용할 수 있어야 한다.

## 4. 모든 작업에 적용할 완료 정의

하나의 작업에는 고유 ID, 연결된 명세 요구, 책임 역할, 선행 작업, 변경 범위, 수용 기준, 검증 방법, 증거 경로, 검토 상태, 배포/복구 방법이 있어야 한다. 코드 PR과 교육 콘텐츠 변경을 연결해 추적한다. 형식적인 체크리스트를 통과시키기 위해 근거 없는 상태를 입력하지 않는다.

콘텐츠의 기본 흐름은 Draft → In Review → Verified → Published이며 오류 발견 시 Revision Required로 되돌린다. 검토자는 무엇을 확인했고 어떤 시험 기준/모델 버전을 확인했는지 남긴다. 공식 문항이나 mark scheme은 사용 권리를 확인하지 않고 복제하지 않는다. 수치 정답은 허용 규칙을, 서술 답변은 자기 점검 범위를 명시한다.

단계 종료 시에는 ‘통과 / 보완 후 재검사 / 선행 결정 대기’ 가운데 하나를 기록한다. 다음 단계의 선행 조건이 충족되기 전에는 해당 기능을 완료했다고 발표하지 않는다.

## 6. 일정 산정과 운영 방식

전체 교육과정의 목표 개수와 검토 인력이 미정이므로 지금 전체 완공일을 약속하지 않는다. 다음 방식으로 산정한다.

1. P0에서 범위·검토자·가용 시간을 정한다. P2에서 목표 수와 재사용 가능한 콘텐츠 묶음을 센다.
2. P3에서 실제 작성·개발·독립 검토·수정·검증 시간을 각각 기록한다. 대기 시간도 따로 기록한다.
3. P4 이후 두 제작 주기에서 처리량을 다시 측정한다. 단순 개수뿐 아니라 실험 난이도, 긴 수식, 평가 형식 차이를 분리한다.
4. 잔여 작업을 역할별 가용 시간과 검토 처리량으로 나누고, 선수 관계와 검토 대기를 반영해 범위별 일정 구간을 제시한다. 내용 범위를 바꾸면 일정을 다시 산정한다.
5. 한 번에 개발 중인 묶음은 1개, 검토 대기 묶음은 최대 2개로 제한한다. 검토 적체가 생기면 초안을 계속 늘리기보다 수정·검증을 우선한다.

업데이트 단위는 ‘개념 묶음 + 검증 증거’다. 매 주기의 기록에는 완료한 요구 ID, 새로 발견한 위험, 실패한 검사, 다음 통과 조건을 남긴다. 계획 수량은 목표이고 실제 완료량으로 자동 변환하지 않는다.

## 7. 주요 위험과 대응

- **연도/응시 경로 오류:** 과목별 판본 고정, 응시 분류와 제품 깊이 분리, 연도 변경 차이 검사로 막는다.
- **화려한 시뮬레이션의 잘못된 설명:** 계산/애니메이션 분리, 명시적 모델, 독립 계산, 설명용/실측 구분을 통과 조건으로 둔다.
- **검토자 부재:** 미검토 표시를 유지하고 정식 자료 출시를 보류한다. 자동화로 과목 검토를 대체하지 않는다.
- **너무 큰 첫 출시:** P5의 12/4/32 상한과 세 연결 주제로 제한하고, P6에서 단원 묶음으로 확장한다.
- **채점에 대한 과장:** 정량 규칙을 검증하고 서술형은 자기 점검으로 제공한다. 공식 점수와 동등하다고 표현하지 않는다.
- **작은 화면과 느린 기기에서의 실패:** 초기부터 SVG·터치 크기·긴 수식·Canvas 비용·실기기 검사를 포함한다.
- **권리와 개인정보:** 원문 문제 무단 복제를 배제하고, 계정과 추적을 핵심 학습의 선행 조건으로 만들지 않는다.
