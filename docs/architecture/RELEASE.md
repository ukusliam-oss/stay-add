# P1 배포와 복구

기록일 2026-11-01. 공개 호스팅은 기존 GitHub Pages를 유지한다. 별도 Sites 서비스의 식별자는 보존하며 해당 서비스에 중복 배포하지 않는다.

## 배포

1. 변경은 `feat/p1-static-structure`에서 작업한다. 기존 다른 프로젝트와 P0의 기준선 해시를 변경하지 않는다.
2. `npm ci --ignore-scripts`, `npm run verify`가 통과해야 한다. G0의 `not_ready`는 기술 검사 성공과 별도로 공개한다. 정식 학술 검토 완료 자료를 새로 배포하지 않는다.
3. 검증한 변경을 `main`에 반영하고 `github` 원격에 푸시한다. 보호 설정을 우회하거나 강제로 푸시하지 않는다.
4. `Verify and deploy GitHub Pages` 워크플로는 Node 24에서 다시 설치·빌드·검사한다. 성공한 산출물만 Pages에 올린다. `dist/`를 수동으로 커밋하지 않는다.
5. 성공한 실행의 커밋과 공개 URL을 확인하고 홈·개념 심화 주소·Lab·Index·스타일/스크립트를 검사한다. 실패하면 이력 재작성 없이 수정 커밋으로 재실행한다.

## 복구 지점과 확인한 범위

P1 직전 정상 커밋: `71247758d64b59e18ead70c34b8eda7a7b630d34`. 성공한 이전 Pages 실행: `41212385483`. 해당 커밋은 기존 단일 페이지 산출물과 당시 워크플로를 포함한다.

이 커밋을 `git archive`로 Git 제외 `.sites-local/p1-rollback/`에 추출하고, 그 복원본에서 `npm run check`를 실행했다. 기존 구문 검사·P0 기록·11개 회귀 테스트가 모두 통과했다. 공개 서버를 이전 버전으로 바꾸는 실제 롤백은 이번 작업에서 실행하지 않았다. 로컬 복원 가능 확인과 실제 운영 복구 연습은 다른 증거다.

## 복구 절차

P1을 도입한 하나의 변경 커밋을 되돌리는 새 커밋을 만든다. `git log`에서 해당 커밋을 확인한 뒤 깨끗한 작업 공간에서 `git revert <도입 커밋>`을 사용한다. 추가 변경이 누적된 경우 충돌을 검토하고 필요한 역변경만 적용한다. `reset --hard`나 force push로 공유 이력을 바꾸지 않는다.

P1 전체를 되돌리면 이전 `dist/`와 빌드 없는 워크플로도 함께 복원된다. 해당 버전의 `npm ci --ignore-scripts`와 `npm run check`를 통과시킨 뒤 `main`에 푸시하고 Pages 실행 성공·공개 홈·Lab 조작을 확인한다. Astro 구조를 유지하며 일부만 되돌릴 때는 `npm run verify`로 새로 생성한 `dist/`를 검증한다.

GitHub Actions에서 과거 실행을 재실행하는 것만으로는 현재 `main`의 내용과 일치하는 복구 이력이 남지 않으므로, 위의 되돌림 커밋 방식으로 소스와 배포를 연결한다. P1에서 새로 생긴 심화 URL은 이전 버전에 없으므로 복구 시 홈 진입과 기존 `#lab` 등 주소를 우선 확인한다.
